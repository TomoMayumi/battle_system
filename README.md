# おつかれさま杯

打ち上げ用のミニゲーム集計ツール。初期設定は新人13人・講師2人ですが、開始前に4〜64人で設定できます。スマホで出番と順位を閲覧し、共有URLを知る誰でもログインなしで結果を入力・訂正できます。

## 公開先

- Web: https://battle-system-tm-20261014.web.app/
- GitHub: https://github.com/TomoMayumi/battle_system
- Firebase: `battle-system-tm-20261014`、無料Spark、Firestore東京（asia-northeast1）。
- Google認証設定: https://console.firebase.google.com/project/battle-system-tm-20261014/authentication/providers

利用前にGoogleログインを有効化し、主催者が公開サイトでイベントを作成してください。参加者には作成後のイベント閲覧URLを共有します。

## ローカルで試す

Node.js 22.12以上とnpmを使用します。

```powershell
npm ci
npm run dev -- --host 127.0.0.1 --port 5182
```

http://127.0.0.1:5182/ を開き、「司会」で人数・名前・予定対戦数・1枠の本数・表彰人数を設定して「保存して開始」。Firebase未設定時は端末内の試用データです。別スマホとは共有されません。

Firebase設定後も `?demo=1` でローカル試用できます。試用データとクラウド結果は別保存です。

## 本番公開

[Firebase無料プランの設定・公開手順](docs/FIREBASE.md)を参照してください。Hosting・Firestore・Authenticationのみを使い、Sparkのまま公開します。主催者のGoogleログインとFirebaseプロジェクト設定は必要です。

## 当日の操作

- 主催者は作成したイベントURLを保管。イベント一覧は自動取得しません。
- 名前は新人・講師それぞれの欄へ改行区切りで一括入力。空行は無視し、前後の空白は除去します。「個別」では人数の増減と名前の個別修正ができます。名前は重複なし・1〜24文字。
- 人数は4〜64人、予定対戦数は1〜200対戦。人数・名前・1枠の本数は開始前のみ変更できます。
- 参加者はQRコードの共有URLを開き、自分の名前を選択。
- タブは「進行」「順位」「対戦表」「司会」。司会権限がない参加者には「司会」は表示しません。「進行」に現在・次の対戦と結果入力をまとめ、司会には管理操作だけを置いています。
- 開始後は誰でも「進行」内の「結果入力」でゲーム名と4人の順位を入力。4人のつまみをドラッグし、左から順位順に並べます。左右ボタンや、つまみにフォーカスしてスペース・左右キーでも並べ替え可能です。
- 同着は2人目以降の「同率」をチェックすると前の人と同率になり、次の順位を自動で飛ばします。全員同率なら3つともチェック。並べ替えて離れた組の同率は解除されます。順位・得点を確認して保存してください。ログイン不要で、保存後は次の未記録本へ移動。
- 「直前の入力を修正」で最後に保存した本を開き直して訂正できます。過去の対戦を選択して訂正・取消も可能。履歴は最新100件を保存。
- 参加者設定・開始/休憩・延長・順位確定は引き続き司会者のみ。確定後は誰も結果を変更できません。投影画面は閲覧専用です。
- 離席などで出場者を交代する場合は、司会で対戦を選び「この対戦の出場者を変更」。現在の出場者と、その対戦に出ていない登録済みの代役を選んで確定します。席はそのまま引き継ぎ、得点は代役に付きます。登録メンバーの追加・削除・名前変更は行いません。
- 「以降の出番も調整」は、代役の後続の未記録対戦のうち、交代前の人が出ていない最初の枠と出番を交換します。交換できれば各人の予定参加回数を維持できます。交換先がない場合やチェックを外した場合は、以降の組み合わせはそのままです。全対戦の再抽選は行いません。
- 出場者変更は対戦単位で、その対戦の1本でも記録済みなら変更不可。2本目だけ別人にはできません。別端末で出場者が変わると、古い順位入力は保持して保存を止めます。「出場者の変更を反映」で入力を破棄して読み直すか、内容を控えてから選び直してください。
- 未実施の2枠で出番を相互交換。各人の予定参加回数を維持します。講師の配置と司会役も確認してください。
- 開始後は「対戦を追加」で延長可能。既存の対戦表・記録済み結果を保持し、出番の少ない人を優先して追加します。最大200対戦。
- 全結果が揃うと「順位を確定」が有効。時間切れなら1本以上記録した後に「途中終了」で未記録を残して確定できます。
- 確定後は結果・延長・表彰人数の変更はできません。まだ継続する可能性がある場合は確定せず休憩にしてください。
- タブレットは入力端末として利用。共有メニューの投影画面は接続できた場合だけ使用。

時間配分と機材確認は[イベント進行案](docs/EVENT.md)にまとめています。

## 採点・対戦表

4人戦を横並びで表示。初期設定の15人・15対戦なら全員4枠、1枠1本なら1人4本、2本なら8本です。人数と予定対戦数によっては参加回数に差が出ます。割当は出番の少ない人を優先し、その中で連続出番、講師同士の同時参加、同じ対戦相手・席位置の繰返しを可能な範囲で避けます。総当たりではなく、少人数や出番交換後にこれらを完全に保証するものではありません。

1〜4位は4・3・2・1点。同着は占有する順位の平均点。例：1・1・3・4位なら3.5・3.5・2・1点。順位は平均得点（合計点÷実施本数）、同点なら1位率（1位回数÷実施本数）で決定。それも同じなら同率順位。未参加者は順位対象外です。画面の平均点・率は丸めて表示しますが、順位は丸めず比較します。全員の本数が等しければ以前の合計点・1位回数順と同じ順位です。

途中終了・延長でも本数の多さだけで有利にならないよう平均で比較しますが、少数試合には運の影響が大きくなります。可能なら全員の出番を確保してから表彰してください。表彰は順位が1位以内／3位以内の全員を表示するため、同着で人数が増えることがあります。

## 保存・障害対応

クラウドは1イベント1ドキュメント。更新時はトランザクションとrevisionで競合を検出。閲覧は変更購読で、秒ごとの全件取得は行いません。再接続やルール評価にも読取が発生するため、使用量はFirebaseコンソールで確認してください。

共有URLを知る人は誰でも結果を入力・訂正・取消できます。入力者の本人確認は行わず、参加者の履歴名は「参加者」です。URLはイベント参加者のみに共有し、公開SNSには投稿しないでください。荒らし対策や書込回数制限を備えた仕組みではありません。

未送信入力は入力した端末に保存し、再読み込み後も復元。復旧後は「再送」。別端末の更新と衝突したら自動上書きせず、未送信を書き出してから入力を取消し、最新結果を確認して手動で反映します。未送信付きバックアップは直接読込できません。JSON内の `unsent` と `event` を控えとして使えます。

共有済みデータはJSONバックアップと順位CSVに書き出せます。バックアップ読込は、クラウドでは新しいイベントを作り、ローカルでは試用データを置き換えます。確定済みを読み込んでも確定状態を維持。有料自動バックアップ機能は使いません。

最初に画面を読み込めていればキャッシュ表示できますが、初回アクセス・ログイン・クラウド保存には通信が必要。障害時は紙で対戦番号・本数・4人の順位を控え、復旧後に入力してください。

## 検証

```powershell
npm test
npm run lint
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:rules
npm audit --omit=dev
```

ルールテストはJava 21以上が必要。このPCではユーザー領域の `party-night-tools/jdk-21*` を検出して子プロセスにだけ指定します。他の環境はJava 21を用意してください。`demo-party-night` のローカルエミュレーターだけに接続し、本番データには触れません。ブラウザーテストはPC・スマホ・タブレットのChromiumで実行。生成物は `test-results` に保存します。

Firebase CLIは開発用です。最新版でも一部推移依存に監査警告があるため、未信頼の設定・パターンを使わず、公開前に `npm audit` を再確認してください。本番サイトにCLIは配布しません。
