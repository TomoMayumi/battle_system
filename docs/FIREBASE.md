# Firebase無料プランで公開

公開環境は `battle-system-tm-20261014`、URLは https://battle-system-tm-20261014.web.app/ です。以下は設定の確認・再作成・再公開の手順です。

課金未接続とGoogle認証設定は、CLIログイン後に次の読取専用コマンドで確認できます。認証トークンやOAuthクライアント秘密鍵は表示しません。

```powershell
node scripts/firebase-check.mjs battle-system-tm-20261014 --check-auth
```

`--enable-firestore` を付けた場合だけ、課金未接続を確認してFirestore APIを有効化します。確認スクリプトはFirebase CLIの内部モジュールを利用するため、CLI更新時には動作確認が必要です。

## 1. プロジェクトを用意

1. https://console.firebase.google.com/ に主催者のGoogleアカウントでログイン。
2. 打ち上げ専用の新規プロジェクトを作成。既存アプリとデータ・無料枠を分離。
3. Sparkプランを維持。課金アカウントをリンクせず、Blazeにアップグレードしない。Analyticsは不要。
4. ウェブアプリを登録。SDK設定のapiKey・authDomain・projectId・appIdを控える。
5. `.env.example` と同じ4項目を `.env.local` に設定する。

これらのWeb設定値は公開識別子であり、管理用の秘密鍵ではありません。サービスアカウント鍵・パスワード・ログイントークンをWebコードやチャットへ貼り付けないでください。

## 2. 認証・データベース

1. Authentication → ログイン方法でGoogleを有効化し、サポートメールを選択。
2. Cloud FirestoreはStandardエディション・デフォルトデータベースを作成。場所は利用地域に合わせて選択。場所は後から変更できない点に注意。
3. 本番モードで作成。誰でも書けるテストモードのまま使わない。
4. このリポジトリのルールを公開するまでは読取・書込ができなくても正常。
5. 認証の承認済みドメインに公開先の `PROJECT_ID.web.app` を確認。ローカルでクラウドログインを試す場合は使用する `localhost` または `127.0.0.1` も登録。

## 3. ビルド・公開

プロジェクトフォルダーで実行。認証はブラウザー上で本人が行います。

```powershell
npm ci
npx firebase login
npm test
npm run lint
npm run build
npx firebase deploy --project YOUR_PROJECT_ID --only hosting,firestore:rules,firestore:indexes
```

`YOUR_PROJECT_ID` は実際のプロジェクトIDに置換。`firebase init` は不要。`.env.local` を変更した場合は再ビルド・再公開。App Hosting・Cloud Functions・Cloud Storage・独自ドメインは使いません。

## 4. イベント作成と共有

1. 公開URLを開いてGoogleで司会者ログイン。
2. 「イベントを作成」。作成者が主催者として登録される。
3. URLに `?event=32桁のID` が付く。このURLをブックマーク・控えとして保管。
4. 「司会」で4〜64人のニックネーム、予定対戦数、本数、表彰人数を保存。名前は改行区切りで一括入力できます。
5. もう1人の講師が同じイベントURLでGoogleログインし、アカウント画面のUIDを主催者に渡す。
6. 主催者が「もう1人の司会者」にそのUIDを登録。最大2人まで編集可能。
7. 共有QRコードは閲覧専用URL。参加者はログイン不要。投影用URLも同じ結果を表示。
8. スマホ2台の別ブラウザーで、共有更新・閲覧専用・再読み込みを事前確認。

共有URLを知る人は結果を読めます。アクセス制御付きの社内限定公開ではありません。氏名・社員番号・会社情報・写真などは登録せず、URLを公開SNSへ投稿しないでください。IDを推測しにくくし一覧取得を拒否していますが、機密情報を守る方式ではありません。

## 無料枠と保管

2026-10-14に公式資料で確認した枠：Firestoreは保存1GiB、読取50,000/日、書込20,000/日、転送10GiB/月。Hostingは保存10GB、転送10GB/月。15人・数十更新の通常利用は小規模ですが、再接続・繰返しアクセスや第三者のアクセスで上限に達する可能性があります。Sparkでは超過時に制限される場合があり、有料の自動継続はしません。無料枠・仕様は変更されるため公開時にも確認。

- https://firebase.google.com/docs/firestore/quotas
- https://firebase.google.com/docs/hosting/usage-quotas-pricing

終了後はJSONとCSVを書き出して保管。自動の有効期限はありません。アプリからの削除は拒否しているため、不要なデータは主催者がFirebaseコンソールから削除。専用プロジェクトの保管期間は主催者が決めてください。

## セキュリティの範囲

ルールで認証なしの書込・一覧取得・主催者IDの変更・権限昇格・開始後の参加者/本数変更・確定後の更新を拒否。人数は4〜64人、対戦数は1〜200で検証します。採点、割当、同着の詳細検証はアプリ側で行います。延長は記録を保持して追加し、途中終了は未記録を残して平均点で確定します。権限を持つ司会者が直接データを書き換える不正を防ぐ審判システムではありません。編集者は信頼できる講師だけに限定してください。

旧15人・15対戦のイベントは再登録不要です。更新後は各端末でページを再読み込みしてください。人数変更は開始前のみ可能で、確定済みイベントの再開・延長はできません。
